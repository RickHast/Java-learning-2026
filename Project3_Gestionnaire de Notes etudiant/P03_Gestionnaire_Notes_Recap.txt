OBJECTIF DU PROJET
──────────────────
Créer un programme console qui saisit les notes d'un étudiant,
calcule sa moyenne, affiche sa note min/max, et délivre une mention.

FONCTIONNALITÉS DÉVELOPPÉES
────────────────────────────
  ✅ Saisie du nom et prénom de l'étudiant
  ✅ Saisie du nombre de matières (> 0, validé)
  ✅ Saisie de chaque note (0.0 à 20.0, validée)
  ✅ Calcul de la moyenne (calculateAverage)
  ✅ Recherche du min et max (findMinNote / findMaxNote)
  ✅ Attribution d'une mention selon des seuils (getMention)
  ✅ Affichage d'un bulletin formaté (%.2f)
  ✅ Option "nouvel étudiant" avec boucle do/while
  ✅ Architecture propre : une méthode = une responsabilité

┌─────────────────────────────────────────────────────────────────────┐
│  NOTION 1 — Tableaux primitifs (double[])                           │
└─────────────────────────────────────────────────────────────────────┘
RÔLE :
  Stocker une collection de valeurs du même type, à taille fixe.

SYNTAXE :
  double[] notes = new double[5];  // tableau de 5 doubles (0.0 par défaut)
  notes[0] = 13.5;                 // accès par index (commence à 0)
  notes[4] = 18.0;                 // dernier élément (index = length - 1)
  int taille = notes.length;       // nombre d'éléments

RÈGLE FONDAMENTALE :
  Créer le tableau APRÈS avoir connu sa taille :
  ✅ int n = scanner.nextInt();
     double[] notes = new double[n]; // n est connu

  ❌ double[] notes = new double[n]; // n = 0 → tableau vide !
     n = scanner.nextInt();

DIFFÉRENCE double[] vs ArrayList<Double> :
  double[]         → taille fixe, connue à l'avance, plus rapide
  ArrayList<Double>→ taille dynamique, inconnue à l'avance, plus flexible
  → Dans P03, on connaît le nombre de matières avant de créer le tableau
    donc double[] est le bon choix.

┌─────────────────────────────────────────────────────────────────────┐
│  NOTION 2 — Boucle for classique vs for-each                        │
└─────────────────────────────────────────────────────────────────────┘
FOR CLASSIQUE — quand l'index est nécessaire :
  for (int i = 0; i < notes.length; i++) {
      notes[i] = scanner.nextDouble(); // ← on a besoin de i pour écrire
  }

FOR-EACH — quand on lit seulement :
  double sum = 0;
  for (double note : notes) {
      sum += note; // ← on lit chaque valeur, pas besoin de l'index
  }

RÈGLE :
  Écriture dans le tableau    → for classique (besoin de l'index)
  Lecture seule du tableau    → for-each (plus lisible)

┌─────────────────────────────────────────────────────────────────────┐
│  NOTION 3 — Algorithme findMin / findMax                            │
└─────────────────────────────────────────────────────────────────────┘
PRINCIPE :
  Supposer que le premier élément est le min (ou max),
  puis parcourir le reste pour trouver un candidat plus petit (ou grand).

CODE :
  static double findMin(double[] notes) {
      double min = notes[0];             // hypothèse initiale
      for (int i = 1; i < notes.length; i++) { // partir de l'index 1
          if (notes[i] < min) {
              min = notes[i];            // nouveau minimum trouvé
          }
      }
      return min;
  }

POURQUOI i = 1 et pas 0 ?
  notes[0] est déjà la valeur de référence.
  Commencer à 1 évite de se comparer à soi-même → optimisation.

┌─────────────────────────────────────────────────────────────────────┐
│  NOTION 4 — Méthode avec retour (return direct)                     │
└─────────────────────────────────────────────────────────────────────┘
VERSION AVEC VARIABLE INTERMÉDIAIRE (débutant) :
  static String getMention(double average) {
      String mention = "";
      if (average >= 16) mention = "Excellent";
      else if (average >= 14) mention = "Very Good";
      // ...
      return mention;
  }

VERSION AVEC RETURN DIRECT (recommandée) :
  static String getMention(double average) {
      if (average >= 16) return "Excellent";
      if (average >= 14) return "Very Good";
      if (average >= 12) return "Good";
      if (average >= 10) return "Fair";
      return "Fail"; // cas par défaut
  }

AVANTAGES du return direct :
  → Plus lisible, moins de variables inutiles
  → Chaque condition sort immédiatement
  → Pas besoin de else if → les return successifs suffisent

┌─────────────────────────────────────────────────────────────────────┐
│  NOTION 5 — Passage par valeur vs par référence                     │
└─────────────────────────────────────────────────────────────────────┘
EN JAVA :
  Primitifs (int, double, boolean...) → passés par VALEUR (copie)
  Tableaux et objets                  → passés par RÉFÉRENCE

CONSÉQUENCE :
  static void modifier(int n) {
      n = 99; // modifie la COPIE locale, pas la variable originale
  }
  int x = 5;
  modifier(x);
  System.out.println(x); // → 5 (inchangé)

  static void remplir(double[] notes) {
      notes[0] = 18.0; // modifie le VRAI tableau (référence partagée)
  }
  double[] tab = new double[3];
  remplir(tab);
  System.out.println(tab[0]); // → 18.0 (modifié !)

RÈGLE :
  Si tu veux modifier un int/String dans une méthode → retourne-le
  Si tu veux modifier un tableau → passe-le en paramètre

┌─────────────────────────────────────────────────────────────────────┐
│  NOTION 6 — scanner.nextLine() après nextInt() / nextDouble()       │
└─────────────────────────────────────────────────────────────────────┘
PROBLÈME :
  nextInt() et nextDouble() lisent la valeur mais laissent le \n
  (touche Entrée) dans le buffer. La prochaine lecture de texte
  récupère ce \n au lieu d'attendre la saisie de l'utilisateur.

SOLUTION :
  subjects = scanner.nextInt();
  scanner.nextLine(); // ← vider le \n résiduel (toujours après nextInt)

QUAND L'APPLIQUER :
  ✅ Après nextInt()   suivi d'une saisie texte
  ✅ Après nextDouble() suivi d'une saisie texte
  ✅ Dans le catch après une saisie invalide

┌─────────────────────────────────────────────────────────────────────┐
│  NOTION 7 — IllegalArgumentException vs InputMismatchException      │
└─────────────────────────────────────────────────────────────────────┘
  InputMismatchException → mauvais TYPE de saisie (texte au lieu de nombre)
  IllegalArgumentException → bon type mais valeur INVALIDE (note = -5)

  Exemple :
  scanner.nextDouble() → lève InputMismatchException si l'user tape "abc"
  if (note < 0) throw new IllegalArgumentException(...) → valeur hors range

  ❌ Ne jamais utiliser throw new Error() → réservé aux erreurs JVM graves
